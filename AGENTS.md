# Architecture rules
- Card requests use authenticated RPCs and a singleton versioned Card & Delivery Settings record; the insert trigger derives immutable financial snapshots under a shared configuration lock, while step-up-only saves lock the record and audit each changed setting to prevent tampering and conflicting updates.
- Card request translations and validation live in the cards feature module; existing DashboardShell navigation carries customer request destinations without adding another primary bar.
- My Circle uses one unique user/customer row with separate saved/viewed timestamps; auth-scoped RPCs validate active targets and reject ownership, while RLS keeps lists private and returns only direct-profile display fields.
- Shared AuthHeader uses a dedicated desktop settings row because authentication panels stay narrow even on wide screens; mobile reuses MobileHeaderMenu.
- Home/My Circle/Profile destinations share PrimaryNavigation; DashboardShell replaces its existing mobile bar rather than stacking a second bar.
- Headers reuse MobileHeaderMenu and existing appearance/language hooks below their existing breakpoint (sm for public/auth, lg for DashboardShell); Radix Popover owns dismissal and focus rather than a parallel navigation state system.
- ProfileEditor owns the existing profile form in details or appearance mode; updates persist only that mode's fields so separate editors cannot overwrite unrelated settings.
- Link icon overrides use the existing links.icon column and a shared allowlisted resolver; invalid or absent values fall back to the link type icon.
- Company support uses a single reusable CustomerService link per page, in normal document flow to avoid covering navigation or profile links.
- Privileged access = admin role in user_roles AND a live admin step-up session bound to the current sign-in session (is_admin()); admin roles change only through owner-only database functions, never direct table writes — so hidden UI never grants access.
- Leaderboard pages come from a server-side paginated database function returning global ranks and a total count, so pages stay consistent without downloading every profile.
- App-served video ships as both H.264 MP4 and VP9 WebM sources from CDN assets; homepage uses a stable 16:9 frame with object-contain so the recording is never cropped or stretched.
- Homepage reuses PrimaryNavigation inside one desktop header and MobileHeaderMenu below lg; its existing bottom navigation remains the only mobile primary bar.
- Physical cards use serial_cards (unique OSH- serial, one current owner, separate assignment/activation states) changed only via SECURITY DEFINER RPCs that lock rows and append serial_card_events; /OSH-<8> (and legacy /s/<serial>) is matched before username lookup and resolves through resolve_serial, while customers claim unassigned cards only via claim_serial, so the printed URL never changes and the database stays the source of truth.
